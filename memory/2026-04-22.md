## Product context

- **Product snapshot**: Canvas Studio is an open-source canvas editor for live streaming rooms and video editing. Users are content creators building dynamic overlays with images, avatars, text bubbles, animations. Primary journey: drag/drop elements on canvas, real-time edit in live/editor modes, timeline for video, export/share.
- **Business goal (this quarter)**: Growth via feature completeness/parity (e.g., editor vs live modes), retention through polished UX, aim for GitHub stars/demo usage.
- **Current pain**: 
  1. Transformer rotation disabled (hardcoded false in Player/AvatarElement despite sync logic).
  2. Align/distribute toolbar missing in EditorPage (video/timeline) vs implemented in ImageEditorPage (live).
  3. Incomplete openspec changes (e.g., enable-element-rotation-align-toolbar-parity has proposal but no design/tasks).
- **Constraints**: React 18/TS + react-konva/Mantine, monorepo with NestJS backend, no openspec CLI installed (blocks proposal/apply), gh CLI missing (blocks PRs), Node 22.
- **Success metrics**: Feature parity (rotation/align work in both modes), no regressions in transformer (tested snaps/keepRatio), demo usage (draw.rosendo.fun visits), GitHub PRs merged.
- **Assumptions**: Prioritize editor parity as recent PD (Apr 19) recommended rotation fix (Plan A, highest ROI). Business goal inferred from README/opensource focus. No user metrics available.

## Requirement plans

### Plan A — Defect fix: Complete rotation enablement + align toolbar parity

**Problem statement**: Rotation hardcoded `false`; align/distribute toolbar absent in EditorPage despite PR#13 implementation in ImageEditorPage — breaks feature parity.

**Target users**: Video editors using timeline mode (EditorPage).

**Proposed solution (1 paragraph)**: Set `rotateEnabled=true` on Transformers in CanvasPlayer/AvatarElement; port align/distribute buttons from ImageEditorPage to EditorPage toolbar (reuse logic for left/right/center/top/bottom/distribute H/V); update selection store sync; test snaps/keepRatio.

**Scope**:
- In: Transformer props, EditorPage toolbar port, store sync.
- Out: Custom rotation limits, mobile gestures, backend.

**Risks & mitigations**:
- Regression in existing transforms: Unit test transformer state; manual test snaps.
- Toolbar UI mismatch: Screenshot parity check.

**Dependencies**: Existing align PR#13 code; konva utils.

**Success metrics**: Rotation UI draggable in both pages; align works ≥3 elements; no console errors.

**Rough effort**: 0.5-1/2 person-weeks (small, reuse code).

### Plan B — New feature: Implement layer panel

**Problem statement**: No layer list/panel for managing z-order/visibility of canvas elements.

**Target users**: Complex layouts (10+ elements, live/video).

**Proposed solution (1 paragraph)**: Add LayerPanel component (list elements by type/id, drag-reorder zIndex, toggle visibility/lock); wire to editorStore selectedLayer/elements; position as Mantine Panel in sidebar.

**Scope**:
- In: Panel UI, reorder/visibility handlers, store integration.
- Out: Advanced grouping, animation keyframes.

**Risks & mitigations**:
- Store mutation races: Immer patches + optimistic updates.
- Perf with 50+ layers: Virtualize list.

**Dependencies**: editorStore zIndex array; existing branches (feature/layer-panel).

**Success metrics**: Drag-reorder updates canvas order; visibility toggle hides/shows.

**Rough effort**: 1.5-2.5 person-weeks (medium UI+store).

### Plan C — Iteration/optimization: Add undo/redo

**Problem statement**: No history for accidental drags/transforms in editing.

**Target users**: All editors (live/video).

**Proposed solution (1 paragraph)**: Zustand middleware for undo/redo stack (patch history on element/state changes); toolbar buttons Ctrl+Z/Y; limit stack to 50 steps.

**Scope**:
- In: Middleware, buttons, keyboard handlers.
- Out: Per-element undo, export history.

**Risks & mitigations**:
- Memory leak: Cap stack, serialize patches.
- Partial undos: Test multi-element ops.

**Dependencies**: Zustand/Immer; feature/undo-redo branch.

**Success metrics**: Undo 5 transforms; no state corruption.

**Rough effort**: 1-2 person-weeks (store-heavy).
